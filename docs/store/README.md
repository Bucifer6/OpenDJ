# Store media: screenshots, preview videos, listing

Everything in this folder is generated from OpenDJ's own UI with the review-pack tracks (CC0 and original, see
[CREDITS.md](CREDITS.md)), so it can be regenerated after any UI change:

```bash
node scripts/review-pack/build-review-pack.mjs      # dist/opendj-review-pack-<version>.zip (tracks are not committed)
node scripts/review-pack/store-screenshots.mjs      # docs/store/screenshots/<platform>/NN-<scene>.jpg + the feature graphic
node scripts/review-pack/store-video.mjs            # docs/store/video/*.mp4
```

The scripts download / regenerate the tracks on first use into `<os tmp>/opendj-review-pack-tracks` (CC0 tracks
from `freemusicarchive.org` / `files.freemusicarchive.org`, with the licence re-checked on each track page). Options:
`--only=<platform>` / `--scenes=<scene>` (screenshots), `--only=appstore|play` and `--seconds=15..30` (video),
`--no-cc0` (generated tracks only, no network). Ports used: 7941 (screenshots), 7942 (video).

| File | What |
|---|---|
| [`../APP_REVIEW.md`](../APP_REVIEW.md) | Reviewer guide (also `REVIEWER_GUIDE.md` in the zip), review-notes text for both stores |
| [`LISTING.md`](LISTING.md) | Listing copy, keywords, category, age rating hints, URLs, privacy answers (every network call) |
| [`PRIVACY.md`](PRIVACY.md) | Draft privacy policy |
| [`CREDITS.md`](CREDITS.md) | Tracks, licences, SHA-256, measured BPM / key (generated by `build-review-pack.mjs --write-docs`) |
| `screenshots/<platform>/` | Store screenshots; `screenshots/index.json` lists each with its pixel size |
| `video/` | App Store app preview and Google Play promo video (+ poster frames) |

## Sizes used, and where they come from

Checked on 2026-11-21.

### Apple (App Store Connect)

Source: Apple, *Screenshot specifications*,
<https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications/>, and *App preview
specifications*, <https://developer.apple.com/help/app-store-connect/reference/app-preview-specifications/>.

| Platform folder | Pixels | Apple's class | Status on Apple's page |
|---|---|---|---|
| `ios-iphone-6.9` | 1320 × 2868 portrait | iPhone with Dynamic Island, large display (6.9": iPhone 16/17/18 Pro Max, Air…) | Accepted size. If provided, the 6.5" set (iPhone with Face ID, large display: 1284 × 2778 / 1242 × 2688) is not required: "Required if app runs on iPhone and screenshots for iPhone with Dynamic Island (large display) aren't provided". So no 6.5" set is made. |
| `ios-iphone-6.3` | 1206 × 2622 portrait | iPhone with Dynamic Island, medium display (6.3": iPhone 16/17/18 Pro, 17…) | The "Required device sizes" section says: "iPhone: At least one screenshot for iPhone with Dynamic Island (medium display)." Both sets are provided to be safe. |
| `ios-ipad-13` | 2752 × 2064 landscape | iPad 13-inch display | "Required if app runs on iPad" (2064 × 2752 portrait or 2752 × 2064 landscape; 2048 × 2732 also accepted) |

Rules from the same page: 1 to 10 screenshots per size, `.jpeg` / `.jpg` / `.png`, no alpha channel (the JPEGs
have none).

App preview (`video/appstore-preview-iphone-886x1920.mp4`): Apple accepts **886 × 1920** portrait (or 1920 × 886
landscape) for the iPhone large and medium display classes, **15–30 s**, at most **30 fps**, H.264 *"Progressive, up
to High Profile Level 4.0"* in `.mov` / `.m4v` / `.mp4`, audio **256 kb/s AAC, 44.1 or 48 kHz, stereo**, up to 500 MB,
up to three previews per size and language. Apple lists a *target* bit rate of 10–12 Mbps; the file here is encoded
smaller (CRF, max 8 Mbps) because screen content compresses well. If App Store Connect rejects it, re-encode with
`-b:v 10M` (see `store-video.mjs`). iPad previews would be 1200 × 1600 / 1600 × 1200; none is made yet (optional).

### Google Play (Play Console)

⚠ **Not verified this time:** `support.google.com` was blocked by the build sandbox's network policy, so these come
from Google's *Add preview assets to showcase your app* help page as previously published
(<https://support.google.com/googleplay/android-developer/answer/9866151>). Check them in Play Console → *Main store
listing → Graphics* before uploading.

| Asset | Requirement (as published) | Here |
|---|---|---|
| Phone screenshots | 2–8; JPEG or 24-bit PNG (no alpha); each side 320–3,840 px; the long side at most twice the short side. For promotion eligibility: at least 4 screenshots of at least 1080 px (1080 × 1920 portrait / 1920 × 1080 landscape) | `play-phone`: 1080 × 1920 (9:16), 6 images |
| 7-inch tablet screenshots | Up to 8; 16:9 or 9:16; each side 320–3,840 px | `play-tablet-7`: 1080 × 1920 (9:16, portrait). Landscape at a 7-inch size (1024 × 576 CSS px) is not used: the deck controls overlap at that size in the current UI (see below) |
| 10-inch tablet screenshots | Up to 8; 16:9 or 9:16; each side 1,080–7,680 px | `play-tablet-10`: 2560 × 1440 (16:9) |
| Feature graphic | 1024 × 500, JPEG or 24-bit PNG (no alpha) | `play-feature-graphic/feature-graphic-1024x500.png` (24-bit RGB) |
| Preview video | A YouTube URL: public or unlisted, embeddable, no ads (monetisation off), not age-restricted; landscape recommended | `video/play-promo-1280x720.mp4` (16:9, 720p) to upload to YouTube |
| App icon | 512 × 512, 32-bit PNG | not part of this pack (the app's icon in `build/`) |

### Desktop / GitHub / website

`desktop-1080` (1920 × 1080) and `desktop-1440` (2560 × 1440): the desktop app's UI at 100 % and 133 % scale, for
the README, GitHub release notes and a website. No store requirement applies.

## Scenes

| # | Scene | Phone mode (`?local=1`) | Desktop |
|---|---|---|---|
| 01 | `mix` | Two decks playing (house 124 → techno 128, synced), deck 1 shown, deck 2 synced with bass cut and a loop | Same, both decks + mixer + library |
| 02 | `library` | Sampler, collection and tracks with BPM / key / ratings | Tall browser with playlists |
| 03 | `automix` | Automix dialog for the "Review Pack" playlist | Same |
| 04 | `sampler` | Sampler pads and the step sequencer running | Same |
| 05 | `effects` | FX panel: echo on deck 1 (flanger on deck 2) | FX panels on both decks |
| 06 | `video` | — (the mobile apps have no video mixer: not shown, to keep the screenshots accurate) | Video panel with the audio-reactive visualiser |
| 07 | `settings` | Settings → Appearance (themes and skins) | Same |

Nothing personal is on screen: the library holds only the pack, the server's data folder is a fresh temporary one,
and the generated tracks' covers are generated too. The CC0 tracks' embedded covers (which show the artist's logo)
are removed in the pack copies, and the video panel's tab for the optional third-party video source is hidden in
the screenshots, so no third-party branding appears.

## What the owner must do

1. **Release:** run `node scripts/review-pack/build-review-pack.mjs --strict` on a machine that can reach
   freemusicarchive.org and files.freemusicarchive.org, check that it reports all six tracks and no hash warning,
   and attach `dist/opendj-review-pack-<version>.zip` to the GitHub release (the reviewer guide links to the
   releases page).
2. **Privacy policy:** review `docs/store/PRIVACY.md`, add a contact address, publish it at a stable URL (GitHub
   Pages or the repo file URL) and enter it in both consoles.
3. **App Store Connect:** upload `screenshots/ios-iphone-6.9`, `ios-iphone-6.3` and `ios-ipad-13` (pick up to 10
   per size, in order), the app preview, the listing text from `LISTING.md`, the privacy answers ("Data not
   collected"), the age-rating answers, and paste the *Notes* text from `APP_REVIEW.md` §5 under App Review
   Information; attach the review-pack zip there too. No sign-in is required: leave the demo account empty.
4. **Play Console:** upload `play-phone`, `play-tablet-7`, `play-tablet-10` and the feature graphic; upload
   `video/play-promo-1280x720.mp4` to YouTube (unlisted, ads off) and paste its URL; fill in *App access* ("All
   functionality available without restrictions"), *Data safety* ("No data collected or shared"), the content
   rating questionnaire, the target audience and the foreground-service declaration (`LISTING.md`).
5. **Store builds:** sync the native projects with the store update channel, so "Update now" opens the store:
   `OPENDJ_UPDATE_CHANNEL=appstore OPENDJ_APPSTORE_URL=<listing URL> npm run mobile:sync` for iOS and
   `OPENDJ_UPDATE_CHANNEL=play npm run mobile:sync` for Android. Google Play does not allow a Play build to download
   and install APKs itself, which the default `github` channel does.
6. **After the final UI merge:** re-run the two media scripts and look at every image before uploading.

## Known limits of this first set

- **Promo video frame rate:** headless Chromium renders the full desktop UI at about 12–15 fps at 1280 × 720 (about
  5 fps at 1080p), so the Play promo is held frames re-timed to 30 fps and looks less fluid than the app. The App
  Store preview (phone layout) is captured at about 33 fps. For a smoother promo, run `store-video.mjs` on a machine
  with a GPU, or record the desktop app with a screen recorder while playing the same mix.
- **UI issues seen while shooting** (for the people working on the UI):
  the deck controls overlap at 1024 × 576 (a 7-inch tablet in landscape: KEY LOCK over the play button, MASTER over
  the time); at 1280 × 720 the FX panel covers half of the play button (`play-tablet-10/05-effects`); and the step sequencer's hint text wraps one word per line on phones (visible in the phone `04-sampler`
  shots).
- **Keys of the generated tracks:** OpenDJ shows the composed key from the file's tag (for example 8A / A minor for
  *Open Circuit*). OpenDJ's key detector, run on the audio alone, hears a fifth above for the three generated tracks
  (CREDITS.md lists both); BPM matches exactly.
